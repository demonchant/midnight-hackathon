01 / THE PROBLEM

Private contracts still have public state.

A source edit or compiler upgrade can change the public ledger. That change may be easy to miss in a code review—and expensive to discover after release.

TODAY

Schema changes hide in compiler output

Reviewers have to know where to look and compare generated metadata by hand.

RISK

Unexpected disclosure or broken clients

An unreviewed public field can change what applications expose and what downstream code expects.

For Compact contract authors, protocol teams, and reviewers.
02 / THE SOLUTION

Turn the expected public schema into a reviewable policy.

1

Compile the candidate

Run the pinned Compact compiler on the actual source.

2

Read the emitted ledger

Inspect the compiler's generated contract metadata.

3

Compare with reviewed policy

Check fields and compiler/toolchain versions against the team's approved expectation.

4

Pass, block, or report compiler failure

Keep an unreviewed schema change from silently passing the gate.

The same check can run in a local workflow or a pull-request CI job.
03 / LIVE PROOF

BLOCKED

05 / PRIVACY BOUNDARY

A precise claim is a stronger claim.

THE GATE CHECKS

Compiler-reported public state

Whether the observed ledger and pinned toolchain match the policy supplied for that inspection.

THE GATE DOES NOT PROVE

Overall security or privacy

Contract logic, transaction metadata, policy appropriateness, and production readiness need separate review.

The Render demo runs the compiler as an unprivileged subprocess in the service container. Use built-in samples or source you are permitted to share; do not upload secrets.
